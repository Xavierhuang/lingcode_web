Release notes

Changelog

What shipped, when, across the macOS IDE, the /try playground, the lingcode CLI, and LingCode Cloud.

v2.7.54

30 September 2026 Mac

Added

  • the App Store check now looks at accessibility in iOS apps: image-only buttons VoiceOver can't describe, text that ignores the user's text size setting, and buttons smaller than Apple's 44-point minimum. These are warnings, not blockers — Apple doesn't reject for them, but people who rely on these settings can't use the app without them. Each one can be handed to the agent to fix, and it can add Apple's own on-screen accessibility test to the app.
  • when the App Store check is wrong about your app, click "Not accurate" under that problem to hide it for this project. The check strip still shows how many are hidden, and the list is saved in the project (.lingcode/audit-ignore.json) so the command-line lingcode audit respects it too.

Fixed

  • opening a project no longer sits on "Checking Claude Code…" while Xcode is being installed or updated. The Claude check runs on its own, and the Xcode row shows its own progress.
  • the phone in the preview pane no longer shows a black band above the screen, and its Dynamic Island sits where a real phone's does instead of over the clock.
  • the App Store check no longer says an app uses tracking because its code handles location or network errors (didFailWithError). It had been asking apps that track nobody to add a tracking permission message.

v2.7.53

30 September 2026 Mac

Improved

  • the simulator mirror skips frames while its pane is collapsed instead of drawing into an empty view.

Fixed

  • LingCode no longer crashes when you click a simulator in the preview pane on a Mac whose Xcode is too old to accept taps from outside Simulator.app. Clicks there now do nothing instead of closing the app.
  • Intel Macs now receive an Intel update instead of the Apple Silicon one. If an in-app update since June left LingCode unable to open on an Intel Mac, download it once from lingcode.dev and updates work from then on.

Share your link to Messages, Mail, AirDrop or WeChat with the Share button, or copy it; when a friend signs up and enters it within 48 hours, you each get 100 extra free LingModel prompts. You are rewarded for up to 20 friends.

v2.7.51

29 September 2026 Mac

Improved

  • the agent can deploy a server-rendered web app to LingCode Cloud by itself: Next.js, SvelteKit, Nuxt, Astro, TanStack Start and React Router 7. It prepares the Cloudflare build, runs it, uploads the result and waits until the app is live. A brand-new public app is shown to you for approval first.
  • the Deploy button and the agent now update the same web app, instead of each creating its own.
  • the agent can add in-app purchases to an iOS app. It gives the app a ready-made StoreKit client that ties each purchase to the signed-in user and has LingCode Cloud verify it with Apple, and it creates the subscriptions and one-time products in App Store Connect with lingcode iap, priced in every country. Purchases and LingCode Payments subscriptions come back together as what the user has paid for.
  • the App Review check recognises a web checkout shown only on the US App Store, which Apple allows for digital goods, and explains the rules instead of warning it will be rejected.

Fixed

  • a new install of LingCode starts in Simple mode and in Dark appearance, as 2.7.50 intended. It had been starting in the full editor with the System appearance, because every fresh install was mistaken for an existing one.
  • the lingcode command line bundled with LingCode can reach LingCode Cloud's tools again.

LingCode ships the Claude Code binary inside the app, so it opens a Claude tab and signs you in there — and when the binary can't be loaded, the message now says reinstalling LingCode is the fix rather than telling you to install a CLI you already have.
  • The embedded Claude Code terminal falls back to the bundled binary when you have no claude install of your own, instead of showing an install wall.
  • Headless runs no longer carry two directives that only describe the GUI — a product description and a map of Xcode symptoms to LingCode menus, which don't exist outside the app. Together they cost 6,596 tokens per query.

Fixed

  • The Claude tab could open a turn by reading a file path that doesn't exist, then hunt for the file with find. It was running with **no system prompt at all** — an omitted system prompt means empty rather than default in the agent SDK, so the model never received Claude Code's tool guidance or the environment section that states the working directory. It now gets both, which means fewer wasted tool calls and no more invented paths.
  • When the bundled Claude binary couldn't be loaded, the error offered no way forward. The recovery banner was checking for a message nothing in the app produces, so the guidance it was meant to show was unreachable — you got a bare error instead.
  • The first-run tour never appeared for anyone who already had a project open when the app launched. It was triggered only by a state *change*, and for a returning user the state was already correct before the view existed.

v2.7.6

29 August 2026 Mac

Improved

  • Devices connected over Wi-Fi are marked as such. Wireless debugging only needs the phone on the same network, not near you, so a device you can't see is a legitimate build target rather than a stale entry — and when one is unreachable it now explains the actual reason for its transport instead of always blaming a cable.
  • Signing failures arrive with the fix attached. A rejected Apple ID, a device not registered to the team, a profile that predates the device, and a missing profile each say what to do about it, rather than restating the error.
  • Clicking Refresh in the picker during an in-flight refresh no longer does nothing. Concurrent requests were discarded rather than queued, so the manual escape hatch failed in exactly the window you'd reach for it.
  • Signing in to Claude no longer sends you to Terminal. Where the tab used to tell you to run claude and /login yourself, it now offers a /login button that opens a Claude tab and signs you in there.
  • When the bundled Claude Code CLI can't be loaded, the message now explains that LingCode ships it and that reinstalling is the fastest fix, instead of telling you to install a CLI you already have.

Fixed

  • Physical devices showed as "iPhone — Unknown" instead of their model. The devicectl parser read marketingName and productType out of deviceProperties, which contains neither key — both live in hardwareProperties — so every iPhone and iPad on every Mac fell back to "Unknown" whether or not it was reachable. The OS version came from the right dictionary, which is why it kept rendering correctly and hid the bug.
  • The run destination list didn't notice devices connecting. Its refresh was attached to the toolbar button's onAppear, which fires once at launch, so opening the picker never re-read anything — a phone plugged in afterwards stayed invisible while its row advised you to connect the cable you had just connected. The list now refreshes when the picker opens, polls while it's open for devices reachable over the network, and watches USB attach and detach.
  • Builds that failed for signing or provisioning reported "0 errors, 0 warnings" above a green "No issues" checkmark. Every diagnostic pattern required a file, line and column, so the project-level errors xcodebuild emits for signing, provisioning, destinations and schemes matched nothing at all — and the same empty list was handed to the in-app agent, which was told a failing build was clean. A failed build can no longer report zero errors.
  • Long diagnostics split across two reads of the build output were dropped. Each chunk was parsed on its own, so a signing error that straddled the boundary became two fragments that matched nothing and vanished from the Problems list while still failing the build.
  • Device detection now understands Xcode 26. Apple deprecated the three property dictionaries LingCode parsed in favour of a nested one and changed three value shapes in the process; both generations are read, so this keeps working on Xcode 15 and 16 and won't break when the old keys are removed.
