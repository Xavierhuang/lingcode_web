📝 Written ● Intermediate Updated 2026-08-15

How do I connect an agent to Xcode's MCP server?

TL;DR: Xcode 26.3 ships an MCP server. Turn on Allow external agents to use Xcode tools in Xcode > Settings > Intelligence, then run claude mcp add --transport stdio xcode -- xcrun mcpbridge. Your agent can now build, test and read Apple docs itself.

This is the single biggest change to agentic iOS development so far: the agent stops guessing whether its Swift compiles and starts finding out. Everything below is Apple's own supported path, not a workaround.

What Xcode exposes

With agentic coding, Xcode makes its toolchain available over the Model Context Protocol, so any MCP-compatible agent can drive it. In practice that means the agent can:

  • Build the project and read the errors — the feedback loop that used to run through you.
  • Run tests and act on the failures.
  • Search Apple documentation, which pulls in current snippets and samples so it stops writing deprecated APIs from memory.
  • Capture Xcode Previews and check its own UI work visually.
  • Explore the file structure and update project settings through Xcode rather than by hand-editing project.pbxproj.

That last one matters more than it sounds. The most common way an agent wrecks an Xcode project is editing the project file directly; giving it a sanctioned route removes the temptation. See use Claude Code with Xcode for the rest of that problem.

1. Allow external agents in Intelligence settings

Choose Xcode > Settings and select Intelligence in the sidebar. Under Model Context Protocol, turn on “Allow external agents to use Xcode tools.”

Xcode alerts you when an external agent connects and while it is active, so you are never wondering whether something is driving your IDE in the background.

2. Register the bridge with your agent

Xcode ships xcrun mcpbridge as the stdio transport. Register it once per agent.

For Claude Code:

claude mcp add --transport stdio xcode -- xcrun mcpbridge

For Codex:

codex mcp add xcode -- xcrun mcpbridge

3. Verify it registered

claude mcp list
# or
codex mcp list

You want to see an xcode entry. If it is missing, the add command failed silently — re-run it and read the output rather than assuming.

4. Open the project in Xcode before you prompt

This is the step people skip. The bridge talks to a running Xcode with your project open; it does not open one for you. Prompt an agent with Xcode closed and the tools are there but have nothing to act on, which produces confusing "I couldn't build the project" replies that look like a broken install.

Order matters: open the project in Xcode → then start the agent. Not the other way round.

5. Tell the agent the tools exist

Registering a server does not guarantee an agent reaches for it. Add a line to your CLAUDE.md (or AGENTS.md for Codex) so it builds rather than guesses:

## Build
Xcode is connected over MCP. Build with the Xcode tools and read the
diagnostics yourself before telling me something works. Do not edit
project.pbxproj directly — use the Xcode project-settings tools.

Apple explicitly suggests adding hints about Xcode and your project to these files. Generate a CLAUDE.md with init covers the rest.

Where this leaves LingCode

Worth being straight about: if all you wanted was an agent that can build and test, Xcode 26.3 plus Claude Code now does that, and it is free. LingCode is still the better tool when you want several agent sessions at once, a provider you chose rather than one of two, rewindable edits, or Kotlin and a backend in the same window as your Swift — see the Claude Code GUI page. It is not the better tool merely because Xcode's own agent story used to be weak. That gap closed.

LingCode also speaks MCP as a client, so the same Xcode server can be registered there — connect an MCP server covers the general case.

Sources

Apple's documentation for this is Giving external agents access to Xcode, and the feature was announced with Xcode 26.3. Check those before following any third-party guide, this one included — the commands are Apple's and may change with a point release.
