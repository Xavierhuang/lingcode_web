How do I put a website online from LingCode Baby?

TL;DR: Open your project folder, click Deploy in the toolbar (or File ▸ Deploy to LingCode Cloud), sign in when the browser opens, and pick a subdomain. Your site goes live at https://yourname.lingcode.app/ with HTTPS. No host account, no deploy token, no DNS. Deploying again updates the same URL.

The hardest part of a first website isn't writing it — it's the wall that appears afterwards. Hosting accounts, build commands, deploy tokens, nameservers: none of it is about your site, and all of it stands between you and a link you can send someone. LingCode Baby collapses that wall into one button. This page walks through exactly what happens when you press it, and what to do when something goes wrong.

Worth being precise about what gets published, because "deploy" means different things in different tools. Baby uploads the files in your project folder and serves them as a website. If you have an index.html, that's your home page. It is static hosting: your HTML, CSS, JavaScript, and images, served over HTTPS. There's no server-side rendering step and no build pipeline to configure — what's in the folder is what goes online.

That's a deliberate trade. Baby is the small, quiet app: you write a site, you press a button, it's live. If you need a build step, a framework like Next.js or SvelteKit, or a database behind your site, that's the Mac IDE's Cloud deploy instead — same hosting, more machinery.

What you'll learn

  • Where the Deploy button is, and the two ways to reach it

  • The three things that most commonly go wrong, and the fix for each

Before you start

  • A LingCode account. You don't need to create one in advance — the deploy will open your browser and walk you through it the first time.
  • A folder with your site in it. At minimum an index.html. If you asked Baby's chat to build you a site, that's already done.

Deploy it

  1. Open your project folder. File ▸ Open Folder… and pick the folder that holds your site. Deploy is disabled until a folder is open — if you click it first, Baby will tell you so.

  2. Click Deploy. It's in the toolbar at the top of the window. The same command lives at File ▸ Deploy to LingCode Cloud if you prefer menus.

  3. Sign in, once. The first time, your browser opens to the LingCode sign-in page. Finish signing in there and switch back to Baby — it picks up the result on its own; there's nothing to copy or paste. On later deploys this step doesn't appear.

  4. Choose your subdomain. Baby asks for the name your site will live under. Type something short and lowercase — my-portfolio, tea-club, your own name. That becomes https://my-portfolio.lingcode.app/. If the name is taken, Baby says so and asks again; nothing is published until a free name is accepted.

  5. Wait for the upload. You'll see Uploading to LingCode Cloud… and then Deploying to LingCode Cloud…. Small sites take a few seconds.

  6. Open your site. When it finishes, Baby shows Deployed to LingCode Cloud with your live URL and a Copy URL button. That link works for anyone, on any device, immediately. HTTPS is already set up.

Updating your site later. Change your files, click Deploy again, and keep the same subdomain. The existing URL updates in place — you don't get a new link, and you don't need to tell anyone anything. If a browser still shows the old version, do a hard reload (⌘⇧R).

When it doesn't work

  • "Open a folder … before deploying." No project folder is open. File ▸ Open Folder… first.
  • The browser opened but nothing happened. Finish the sign-in in the browser tab, then return to Baby. If the tab was closed too early, just click Deploy again — it will re-open sign-in.
  • "…isn't available." Someone already has that subdomain. Names are first-come, first-served across all LingCode users, so common words go quickly. Add a word: tea-club-oxford.
  • The page loads but is blank. Almost always a missing or misnamed index.html — the file has to be at the top level of the folder you deployed, and the name is case-sensitive.

Using your own domain

A .lingcode.app address is a real, permanent home for a site, and plenty of projects never need more. When you do want yourname.com, you buy the domain from a registrar and point it at your site — that's covered in Connect a custom domain, and if you haven't bought one yet, start with Buy a domain from Cloudflare or Namecheap.
