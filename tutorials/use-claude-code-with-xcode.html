How do I use Claude Code with Xcode?

TL;DR: Commit project.pbxproj before you start, state your deployment target in CLAUDE.md, and give the agent a way to build. Most "Claude Code broke my Xcode project" stories are one of those three missing.

Claude Code is very good at Swift and quite bad at Xcode — not because the model is weak, but because an Xcode project is a large generated property list that no one should be editing by hand, least of all a text-generating agent. Everything below is about keeping the agent on the code and off the scaffolding.

1. Commit the project file first

project.pbxproj is the danger zone. It is machine-generated, order-sensitive, and full of opaque 24-character identifiers. An agent that decides to "add the file to the project" by editing it directly will usually produce something Xcode can still open and cannot build.

Commit it on its own before you start a session:

git add MyApp.xcodeproj/project.pbxproj
git commit -m "Checkpoint project file before agent session"

Now the worst case is git checkout -- MyApp.xcodeproj/project.pbxproj rather than an afternoon of diffing UUIDs. In LingCode this is less pressing because every edit is captured and rewindable — see undo bad AI edits — but the commit costs nothing and works everywhere.

Say it out loud: put "never edit project.pbxproj directly; tell me and I will add the file in Xcode" in your CLAUDE.md. Agents follow explicit prohibitions far more reliably than implied ones.

2. State your deployment target in CLAUDE.md

Swift has a smaller and older public corpus than Python or JavaScript, so an agent left to its own devices reaches for the APIs it saw most often — which are rarely the current ones. The single highest-value line in a Swift CLAUDE.md is the minimum OS version:

## Platform
Minimum deployment target: iOS 18.
Prefer @Observable over ObservableObject, SwiftData over Core Data,
and the current NavigationStack APIs. Do not suggest UIKit unless
there is no SwiftUI equivalent.

Without it you will spend the session declining ObservableObject. Generate a CLAUDE.md with init covers the rest of the file; this is the part people leave out.

3. Give the agent a way to build

This is the difference between an agent that guesses and one that converges. An agent that cannot compile has no feedback signal — it writes plausible Swift, you paste it into Xcode, it fails, you paste the error back. That loop works, but you are the transport layer.

From a terminal, the minimum is a build command it is allowed to run:

xcodebuild -scheme MyApp -destination 'platform=iOS Simulator,name=iPhone 16' build

In LingCode the loop is already closed: build, run and diagnostics are part of the native tool registry, so the agent compiles, reads the errors itself, and iterates without you relaying anything. Your first build walks through it, and explain terminal errors with AI covers the case where you would rather drive.

4. Expect new files to be missing from the target

An agent creates Sources/Feature/ThingView.swift on disk. Xcode does not know about it. The build fails with "cannot find 'ThingView' in scope" — which reads like a syntax error and is actually a membership error.

Two habits make this painless:

  • Prefer adding files through Xcode (or a folder reference / SPM target) so membership is automatic.
  • When "cannot find X in scope" appears right after new files, check target membership before you debug the code. It is almost never the code.

The same error also shows up for an entirely different reason — SourceKit's indexer cascading after a large edit. If the file is in the target, build from the command line to get the truth before chasing it.

5. Keep the session scoped

Long Xcode sessions drift. The agent that has been running for two hours has a context full of build output and will start proposing changes to things you never asked about. Two things help:

  • One concern per session. In LingCode you can run several Claude Code tabs at once, each an independent conversation, so "fix the layout" and "sort out signing" do not share a context.
  • Work on a branch or a worktree. Experiment safely with worktrees is the cheapest way to let an agent be aggressive without gambling your working tree.

What this does not fix

Signing. Nothing above helps with provisioning profiles, and agents are especially confident and especially wrong about them. Fix iOS signing errors is a checklist, not a prompt.
