Tutorials / Tips & tricks / Verify AI code with Quinny
📝 Written ● Intermediate Updated 2026-07-17

Hold AI code to a contract — verify any model’s output with Quinny

Any model can write code fast. Whether it actually meets your spec is a different question — and re-reading the diff every time doesn’t scale. Quinny turns your acceptance criteria into an executable gate that any implementation must pass. The verdict is real tests running real code, not an LLM’s opinion of its own work.

The problem: fast code isn’t verified code

0

An AI coding tool will hand you a working-looking implementation in seconds. The gap is that looking right and being right are not the same, and the only person checking is you — re-reading the diff, hoping you remember every requirement. That doesn’t hold up across a real project, and it gets worse when you swap in a cheaper, faster model to save cost.

The instinct is to ask the model to check its own work. Don’t: a model that confidently wrote a bug will just as confidently tell you it’s correct. Verification has to come from somewhere the model can’t talk its way past.

The idea: write the contract once, gate everything against it

1

Quinny is an executable specification language. You write what “correct” means — concrete acceptance criteria — in a small, reviewable .qn file. That file isn’t code that runs; it’s a durable contract. Quinny compiles its test criteria into a real test suite and runs that suite against any implementation: written by a human, by Claude, by Cursor, in Python, JavaScript, or Swift.

project TodoService

component Store
    goal
        In-memory store of todo items.
    test
        add("milk") returns an int; adding again
        returns a different id.
    test
        a removed id is no longer listed.

Those test lines are the contract. Each one is a precise, checkable promise. The verb Quinny cares about is verify, not generate — it doesn’t compete with the model that writes your code, it holds that code to a standard you own.

How it works, end to end

2

The whole flow is one loop. The contract compiles to a gate; code runs through the gate; anything that fails comes back with the exact expected-vs-got and gets fixed — keeping only the best version, so it never regresses.

The two violet edges are the only places a model is involved: compiling the contract into tests, and writing (or fixing) the code being judged. Everything in between — the gate itself — is a plain test run.

Where the LLM is, and where it isn’t

3

This is the part that makes the reliability real. An LLM touches exactly two edges of the flow and never the middle:

  • Compile — a model reads your criteria and writes the test module. Once.
  • Implement / fix — the model being gated writes the code, and on a failure rewrites it from the specific reason it failed.

The gate itself uses no model. It runs the generated tests as an ordinary subprocess — pytest, node:test, swiftc — and pass/fail is deterministic code execution. You can’t argue a test suite into a green check; you can only satisfy it.

Freeze it for CI. Run quinny verify spec.qn ./impl --emit suite.py once, review the generated suite, commit it, then re-run with --suite suite.py. After that the contract is enforced on every commit with zero model calls — a plain, deterministic test file.

The verify-loop: how a cheap model gets reliable

4

A single pass isn’t the point — the loop is. Implement → verify → feed the failures (with expected-vs-got) back → fix → repeat, keeping the best-scoring version at every step so the code can never come out worse than it went in. In our benchmarks this takes a weak, cheap model from silently shipping broken builds to reliably passing every criterion — matching a frontier model’s output on the same task, at a fraction of the cost.

The loop is only as good as the contract is complete. Quinny enforces exactly what your test criteria cover. A thin contract lets bugs through in the behaviors you never gated — so spend your effort writing criteria that pin down what actually matters. That’s the one piece the tool can’t do for you, and it’s where your leverage is.

Where you already have it

5

Quinny is open-source (pip install quinny) and ships bundled inside LingCode, so the agent can scaffold a contract and verify against it out of the box — no separate install. Point it at a folder and it verifies whatever’s there; hand it plain English with quinny scaffold and it drafts the contract for you to review. Either way, the model does the fallible creative work and a non-negotiable gate holds it to your spec.
